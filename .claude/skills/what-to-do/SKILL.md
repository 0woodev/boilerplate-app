지정된 영역(또는 전체)의 **지금까지 진척 / 미완료 / 블로커**를 정리하고, **다음에 무엇부터 손대면 좋을지** 우선순위 추천을 한다.

**대상 영역:** $ARGUMENTS

(인자 없이 호출되면 → 전체 영역 = `fe`, `be`, `infra` 모두)

---

## 데이터 소스 우선순위 (토큰 절약 중요!)

이 스킬은 토큰을 아끼기 위해 **이미 압축된 컨텍스트**를 먼저 본다.

| 순위 | 소스 | 무엇 |
|---|---|---|
| 1 | `ACTIVITY.md` | 최근 활동 한 줄 요약 (50줄 이내). **메인 데이터.** |
| 2 | `PROGRESS.md` "진행 중 / 다음 세션" 섹션 | 미완료 + 블로커 + 설계만 정리된 항목 |
| 3 | 영역별 `git status -s` + `git branch --show-current` | 미커밋 상태 (가벼움) |
| 4 | `MEMORY.md` 의 project_* / feedback_* | 비코드 컨텍스트 (블로커, 결정사항) |
| 5 | (의심 시에만) 영역별 `git log -3` | drift 검증용 |
| 6 | (필요 시에만) `DOMAIN.md`, 영역별 `CLAUDE.md` | 도메인/구조 질문 있을 때만 |

**금지:** 영역별 `README.md` 50줄 읽기, `git log -10`, 영역별 `CLAUDE.md` 전체 읽기. 위 표의 1~3 만으로 90% 답이 나온다.

## 작업 순서

### 1. 인자 정규화

`$ARGUMENTS` 를 공백/쉼표로 split → 소문자화 → 다음 alias 매핑:
- `fe` / `frontend` → `fe`
- `be` / `backend` → `be`
- `infra` / `terraform` / `iac` → `infra` (be/terraform/, fe/terraform/ 양쪽 포함)
- 빈 입력 / 매칭 실패 → 전체 (fe + be + infra)

매칭된 영역 목록을 명시 (사용자에게 한 줄로 알려줌).

### 2. 메인 컨텍스트 — ACTIVITY.md 한 번 읽기

루트 `ACTIVITY.md` 를 한 번 읽는다. 표를 파싱해서:
- 영역별로 그룹핑
- 가장 최근 항목 5개 정도가 "최근 흐름"
- 영역에 항목이 없으면 → 그 영역은 한동안 손대지 않은 상태

### 3. 진행 중 / 미완료 / 블로커 — PROGRESS.md "진행 중" 섹션만

`PROGRESS.md` 전체를 읽지 말 것. **`## 진행 중 / 다음 세션 이어가기` 섹션 + 그 아래 "미완료" / "알려진 이슈" 표** 만 발췌해서 읽는다 (`grep -n` + 부분 Read 사용).

### 4. ACTIVITY.md 신선도 체크 (drift 감지)

각 대상 영역에 대해:
- `ACTIVITY.md` 에서 해당 영역의 가장 최근 날짜를 찾는다
- `cd <area> && git log -1 --format=%ad --date=short` 의 가장 최근 커밋 날짜와 비교
- **갭 ≥ 3일이면 경고**: "ACTIVITY.md 정체 의심 — 영역 `<x>` 에 최근 커밋 있는데 로그에 누락 가능성. 사용자에게 업데이트 권유."

### 5. 영역별 라이트 스냅샷

각 영역 `<area>` 에 대해 (대상에 포함된 경우만):
- `cd <area> && git status -s | head -20` — 미커밋 변경 (파일 수만 카운트, 내용 추측 X)
- `cd <area> && git branch --show-current` — 현재 브랜치

이게 끝. `git log` / `cat CLAUDE.md` / `cat README.md` **하지 말 것** — ACTIVITY.md 가 이미 그 정보를 담고 있다.

### 6. 다음 후보 도출 (영역별 5개 이내)

후보 카테고리:
1. **🔴 블로커** — 다른 작업 막고 있는 것
2. **🟡 검증 미완** — 코드는 있는데 라이브/E2E 검증 안 된 것
3. **🟢 로드맵** — `PROGRESS.md` 미완료 / 장기 TODO
4. **🔵 위생** — 테스트 미작성, 문서 누락, 미커밋 정리

각 후보에 한 줄 사유. 5개 이내.

### 7. 통합 우선순위 — TOP 3

전 영역 결과를 모아 **TOP 3** 추천:
- 1순위: 임팩트 가장 큰 블로커
- 2순위: 적은 노력으로 큰 진척
- 3순위: 사용자가 마지막으로 손대던 흐름의 자연스러운 다음 단계

각 추천에:
- 한 줄 설명
- 예상 사이즈 (S / M / L — 시간 단위 X)
- 시작 지점 (구체적인 파일/명령)

### 8. 출력 포맷

```markdown
## 분석 대상
- 영역: <list>
- 시점: <today YYYY-MM-DD>
- 데이터 신선도: <ACTIVITY.md 가장 최근 항목 날짜> (drift 감지 시 경고)

## 영역별 요약

### <area>
**현재 브랜치:** <branch> · **미커밋:** <yes/no, 파일 수>
**최근 흐름 (ACTIVITY.md):** <last 2-3 entries 요약>
**블로커:** <if any>
**다음 후보:**
- 🔴 …
- 🟡 …
- 🟢 …

(영역별 반복)

## TOP 3 추천 (전 영역 통합)

1. **<제목>** — <한 줄 설명> · 사이즈: <S/M/L> · 시작: `<file or command>`
2. ...
3. ...

## 메모
- 마지막 세션에서 끊긴 흐름: <if any>
- 검증 미완 항목: <list>
- (drift 감지 시) ⚠️ ACTIVITY.md 갱신 필요: <영역, 마지막 갱신일>
```

## 주의사항

- **ACTIVITY.md 가 진실의 원천** — 의심되면 step 4 의 drift 체크로 검증, 그래도 의심되면 사용자에게 "ACTIVITY.md 가 오래되었을 가능성. 갱신해드릴까요?" 한 줄로 묻기.
- **추측 명시.** 추론한 내용엔 "추정" 표시. 사실인 양 단언 X.
- **메모리 우선.** `MEMORY.md` 의 project_* 메모는 비코드 정보 — 활동 로그와 충돌하면 활동 로그가 더 최근일 가능성 높음.
- **`.credentials/`, `.env`, `.session/`, `.activity/` 안 들여다보지 말 것.** 민감.
- **"앞으로 뭘 할지" 는 추천이지 결정이 아님.** 사용자가 골라야 한다는 점 명시.
